## 싱커드 E2E 테스트 시나리오

서비스의 핵심 사용자 플로우를 실제 브라우저/디바이스 환경에서 검증하기 위한 E2E 시나리오입니다. 스테이징 환경 기준으로 작성했으며, 프로덕션 사전 점검에도 활용할 수 있습니다.

---

## 1. 공통 전제

- **테스트 환경**
  - [ ] 최신 브라우저 (Chrome, Safari)에서 테스트
  - [ ] 모바일/태블릿 뷰포트 1종 이상 테스트
  - [ ] 스테이징 API / DB 사용, 프로덕션과 설정 최대한 동일

- **테스트 계정**
  - [ ] 일반 유저 계정
  - [ ] 관리자 계정 (필요 시)
  - [ ] 소셜 로그인용 테스트 계정 (Google, Kakao 등)

---

## 2. 인증 / 계정

- **회원가입**
  - [ ] 유효한 이메일/비밀번호로 회원가입 성공
  - [ ] 이미 가입된 이메일로 시도 시 적절한 에러 메시지 표시
  - [ ] 비밀번호 정책(길이/문자종류 등) 위반 시 에러 메시지 표시

- **로그인 / 로그아웃**
  - [ ] 올바른 이메일/비밀번호로 로그인 성공, 홈 또는 대시보드로 이동
  - [ ] 틀린 비밀번호 입력 시 에러 메시지 표시, 보안상 적절한 문구 사용
  - [ ] 로그인 상태에서 새로고침 시 세션이 유지되는지 확인
  - [ ] 로그아웃 시 세션/토큰이 정리되고 로그인 페이지로 이동

- **소셜 로그인 (사용하는 경우에만)**
  - [ ] Google 등 소셜 로그인 플로우 정상 동작
  - [ ] 최초 소셜 로그인 시 계정 연동/프로필 정보 저장 확인

- **비밀번호 찾기 / 재설정**
  - [ ] 이메일 입력 후 비밀번호 재설정 메일 발송
  - [ ] 재설정 링크를 통해 새 비밀번호 설정 및 로그인 가능

---

## 3. 대시보드 / 메인 플로우

싱커드의 핵심 기능(예: 프로젝트/작업 관리, 데이터 싱크 등)을 중심으로 시나리오를 구성합니다. 아래는 예시이며, 실제 도메인에 맞게 구체화하세요.

- **대시보드 진입**
  - [ ] 로그인 직후 대시보드로 이동
  - [ ] 나에게 할당된 주요 정보(프로젝트, 작업, 알림 등)가 정상 노출

- **엔티티 생성 (예: 프로젝트 생성)**
  - [ ] 필수 필드를 채워 신규 엔티티 생성 성공
  - [ ] 생성 후 목록/상세 화면에서 방금 생성한 데이터 확인 가능

- **엔티티 수정**
  - [ ] 제목/설명/옵션 등 일부 필드 수정 후 저장
  - [ ] 새로고침 후에도 수정된 내용이 그대로 유지

- **엔티티 삭제 / 보관**
  - [ ] 삭제(또는 보관) 진행 시 확인 모달 노출
  - [ ] 삭제 후 목록에서 사라지거나 보관함으로 이동

---

## 4. 목록 / 필터 / 검색

- **목록 페이지**
  - [ ] 페이지 진입 시 기본 목록이 로드되고, 로딩 인디케이터 동작
  - [ ] 페이지네이션 또는 무한 스크롤이 정상 동작

- **필터**
  - [ ] 상태/날짜/담당자 등 필터 조합 적용 시 목록이 올바르게 갱신
  - [ ] 필터 초기화 시 전체 목록으로 복원

- **검색**
  - [ ] 키워드 검색 시 관련 항목만 노출
  - [ ] 존재하지 않는 키워드 검색 시 “결과 없음” UI 표시

---

## 5. 권한 / 접근 제어

- **권한별 화면**
  - [ ] 일반 유저로 관리자 전용 페이지 접근 시 접근 거부 처리
  - [ ] URL을 직접 입력해도 권한 없는 페이지는 접근 불가

- **로그인 상태 / 비로그인 상태**
  - [ ] 비로그인 상태에서 보호된 페이지 접근 시 로그인 페이지로 리다이렉트
  - [ ] 로그인 후, 원래 접근하려던 페이지로 되돌아가는지 확인

---

## 6. 설정 / 프로필

- **프로필 수정**
  - [ ] 이름/프로필 이미지 등 수정 후 저장, 화면에 즉시 반영

- **알림 설정**
  - [ ] 이메일/푸시 알림 등 On/Off 토글이 정상 동작
  - [ ] 변경된 설정이 새로고침 후에도 유지

---

## 7. 에러 핸들링 / 엣지 케이스

- **네트워크 에러**
  - [ ] API 장애(강제 500/timeout 시뮬레이션) 시 사용자 친화적인 에러 메시지 표시
  - [ ] 재시도 버튼 또는 새로고침 유도

- **권한 만료**
  - [ ] 토큰 만료 상태에서 요청 시 로그아웃 처리 또는 재로그인 유도

- **404 / 500 페이지**
  - [ ] 잘못된 URL 접근 시 404 페이지 노출
  - [ ] 서버 에러 발생 시 500(또는 공통 에러) 페이지 노출

---

## 8. 퍼포먼스 / UX

- **초기 로딩**
  - [ ] 첫 화면 로딩 시간이 허용 범위 이내인지 체감 확인
  - [ ] 로딩 스피너/스켈레톤이 적절하게 노출되는지 확인

- **인터랙션**
  - [ ] 버튼/링크 클릭 시 중복 요청 방지 처리 (로딩 상태, 비활성화 등)
  - [ ] 주요 양식에서 입력 검증 및 에러 메시지 위치/문구 확인

---

## 9. 결제/정산 (해당되는 경우에만)

- [ ] 결제 플로우(상품 선택 → 결제 정보 입력 → 결제 완료) 정상 동작
- [ ] 실패/취소 시나리오에서 적절한 안내 및 상태 롤백
- [ ] 결제 완료 후 영수증/이메일 발송 여부 확인

---

## 10. 회귀 테스트 체크

- [ ] 기존에 보고되었던 주요 버그 케이스 재검증
- [ ] 최근에 변경된 기능(릴리스 노트 기준) 집중 테스트
